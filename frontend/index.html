Clocked APIs

Clocked inspects and protects untrusted support content before any LLM or business logic runs. Every method accepts the raw ticket text (or evidence documents) and returns a structured verdict. In mock mode, all calls are deterministic - no external network calls are made.

MethodPurposeInputMock Behavior
injection(text) Prompt-injection / jailbreak guard on the raw ticket body. Runs first; suspicious tickets are quarantined before PII, extract, decide, or TypeLLM ever run. text (string) - raw untrusted ticket body Flags patterns: "ignore all previous instructions", "bypass the refund policy", "reveal your system prompt". Returns verdict clear / suspicious with an injection boolean and mock: true.
pii(text) Detects and anonymizes PII (person, email, phone, address, credit_card, username) in text used downstream. text (string) Returns anonymized text unchanged; notes no real PII detection in mock. Returns {anonymized_text, mock: true}.
extract(text, fields) Extracts structured fields from free text: issue_summary, category_hint, urgency_hint, request_type, amounts, payment_method_type, refund_requested, currency, entities. text (string), fields (object of field descriptions) Regex-extracts $ amounts, "twice"/duplicate count, "refund" keyword, plan names, company card, currency. Returns {fields: {...}, mock: true}; unextractable fields are null.
decide(state, questions) Boolean billing decisions: is_billing_issue, is_technical_issue, is_account_issue, refund_requested, urgent. state (string), questions (object of question names) Keyword-based answers from ticket text. Returns {answers: {...}, mock: true}.
grounding(documents, question, answer) Verifies a customer-facing refund reply against supporting evidence documents before sending. documents (array of {text}), question (string), answer (string) Returns supported if the reply mentions successful processing and a document shows status: succeeded; otherwise review_required. Returns mock: true.

Usage Example (mock mode)

from app.adapters.clocked import ClockedAdapter

clocked = ClockedAdapter()  # mock_mode=true by default

raw = "Subject: Billed twice\n\nI was charged $49.00 twice for my Pro plan."

# 1. Injection guard - run first on raw untrusted input
guard = clocked.injection(raw)
# -> {"verdict": "clear", "injection": false, "mock": true}

# 2. PII protection
pii = clocked.injection(raw)  # then clocked.pii(raw)
# -> {"anonymized_text": raw, "mock": true}

# 3. Structured extraction
extracted = clocked.extract(raw, {
    "issue_summary": {"description": "Concise customer issue summary"},
    "amounts": {"description": "Any dollar amounts mentioned"},
})
# -> {"fields": {"issue_summary": "refund requested", "amounts": [49.0], ...}, "mock": true}

# 4. Boolean decisions
decision = clocked.decide(raw)
# -> {"answers": {"is_billing_issue": true, "refund_requested": true, ...}, "mock": true}

# 5. Grounding the customer-facing reply
grounding = clocked.grounding(
    documents=[{"text": "Refund TXN-10002 status: succeeded"}],
    question="Was the duplicate charge refunded?",
    answer="Your duplicate charge of $49.00 was successfully refunded.",
)
# -> {"verdict": "supported", "mock": true}

Live mode: set MOCK_MODE=false and CLOCKED_API_KEY. Uses the clocked-sdk Clocked client. Base URL default: https://clocked.rezolve.ai/clocked. Methods map to client.injection, client.pii, client.extract, client.decide, client.grounding.

TypeLLM Typed Workflow

TypeLLM classifies tickets with typed questions, dependencies, source: user fields, and generate()/resume() turns. It produces reliable, typed classification rather than free-form LLM output, and cleanly separates model-inferred fields from externally-verified facts. Refund decisions are never based solely on model output.

QuestionTypeDepends On / SourcePurpose
category string (enum) - Classify the primary support issue: billing, technical, account, other.
urgent boolean - Priority handling; urgency does not authorize a refund.
handling_advice string depends_on: category, urgent One internal next step; verify payment records before refund decisions.
duplicate_confirmed boolean source: user, when: category=billing Trusted provider duplicate evidence; true only when the payment provider confirms a duplicate charge.
refund_amount number source: user, when: category=billing & duplicate_confirmed=true Application-calculated refund amount from the payment adapter; never inferred from the customer message.
reply string depends_on: category, urgent Concise customer reply; never claim refund approval or completion without evidence.
ContractMock BehaviorLive Behavior
generate(context, questions) Returns {status, result, needs_input, resume_state: "mock"}. Billing tickets return status: "needs_input" with needs_input: ["duplicate_confirmed"]; non-billing return status: "completed". Calls TypeLLMClient.generate(context=context, questions=questions()). Returns the SDK generation object; persist via the SDK's supported serialization (do not pickle).
resume(response, answers) Merges answers into the result. If duplicate_confirmed is true and refund_approved is absent, returns status: "needs_input" waiting on refund_approved; otherwise status: "completed". Calls client.resume(response, answers) with the live SDK response object and resolved source: "user" values.

Usage Example

# 1. First turn - classify and collect source:user fields
response = client.generate(
    context=ticket_text,
    questions=[
        Question(name="category", type="string", enum=["billing","technical","account","other"]),
        Question(name="urgent", type="boolean"),
        Question(name="handling_advice", type="string", depends_on=["category","urgent"]),
        Question(name="duplicate_confirmed", type="boolean", source="user", when={"category":"billing"}),
        Question(name="refund_amount", type="number", source="user", when={"category":"billing","duplicate_confirmed": True}),
        Question(name="reply", type="string", depends_on=["category","urgent"]),
    ]
)

# 2. Resolve external facts from the payment provider (authoritative evidence)
duplicate_confirmed = payment_adapter.check_duplicate(ticket)
refund_amount = payment_adapter.compute_refund(ticket)

# 3. Second turn - resume to completion
final = client.resume(response, {
    "duplicate_confirmed": duplicate_confirmed,
    "refund_amount": refund_amount,
})

Mock generate() response (billing ticket)

{
  "status": "needs_input",
  "result": {
    "category": "billing",
    "urgent": true,
    "handling_advice": "Verify provider transactions before refund consideration.",
    "reply": "I'm sorry about the billing issue; our team is checking the payment records."
  },

  "skipped": [],
  "resume_state": "mock"

Live mode: requires TYPELLM_API_KEY and uses TypeLLMClient.generate() and client.resume(). External values are declared as source: "user" and resumed with the live SDK response object. For multi-worker production deployments, persist and restore workflow state only through a documented TypeLLM-supported mechanism - do not rely on in-memory objects across restarts.

Backend API Endpoints

FastAPI server runs on http://127.0.0.1:8000 (interactive docs at /docs). All endpoints return JSON. Default MOCK_MODE=true simulates Clocked, TypeLLM, and payment responses - no real money moves and no external network calls.

EndpointMethodDescription
/health GET Health check; returns status and mock_mode flag.
/stats GET Aggregate stats: tickets processed, refunds issued, quarantined count.
/tickets POST Create and process a support ticket (subject, body, customer_id). Runs the full Clocked + TypeLLM pipeline.
/tickets GET List processed tickets (query: limit, offset). Ordered newest first.
/tickets/{ticket_id} GET Retrieve a processed ticket with Clocked & TypeLLM results.
/tickets/{ticket_id}/approval POST Finance decision: approved, rejected, or needs_information. Returns 409 Conflict if already decided.
/tickets/{ticket_id}/audit GET Full audit trail of events for a ticket.

Create Ticket (POST /tickets)

POST /tickets
Content-Type: application/json

{
  "subject": "Charged twice this month",
  "body": "I upgraded to Pro on the 3rd and my card was charged twice, $49 each time.",
  "customer_id": "CUS-DEMO-1025"
}

Response includes id (e.g. SUP-A1B2C3D4E5F6), status, category, clocked_results, extracted, payment_evidence, refund_amount, final_reply.

Finance Decision (POST /tickets/{id}/approval)

POST /tickets/SUP-A1B2C3D4E5F6/approval
Content-Type: application/json

{
  "decision": "approved",
  "reviewer_id": "finance.manager@example.com",
  "reason": "Provider duplicate reference verified; second charge confirmed"
}

decision: approved | rejected | needs_information. A second decision on an already-decided ticket returns 409 Conflict.

About Clocked Support Intelligence

Reference Engine • v1.0.0

Overview

The Clocked Support Intelligence Engine is a Python/FastAPI reference project that combines Clocked security APIs and TypeLLM typed workflows for support-ticket triage and duplicate-charge resolution. It processes incoming support tickets through a deterministic pipeline: injection inspection, PII protection, structured extraction, decision logic, TypeLLM classification, category-specific handling, payment evidence lookup, finance approval, idempotent refunds, and Clocked grounding of customer-facing replies.

How It Works

  1. Ticket received - Persisted to SQLite with a TICKET_RECEIVED audit event.
  2. Clocked Injection - Inspects untrusted content; suspicious tickets are quarantined.
  3. Clocked PII - Protects text used downstream.
  4. Clocked Extract & Decide - Produce structured billing evidence.
  5. TypeLLM - Classifies category, urgency, and handling advice using typed questions.
  6. Category handler - Billing tickets run payment lookup/duplicate confirmation.
  7. Finance approval - Human decision (approved / rejected / needs_information).
  8. Refund - Idempotent refund executed keyed by ticket.
  9. Clocked Grounding - Verifies the customer-facing refund claim before sending.
  10. Persist outcome - Audit trail and final status recorded.
